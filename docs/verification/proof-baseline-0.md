# Proof Baseline 0

**Status:** executable baseline, 2026-08-01

**Scope:** the implemented notebook graph, λδ kernel, formula host entry point,
WASM boundary, and Bun build

**Non-claim:** this document does not call testing a formal proof

This ledger separates properties supported by executable evidence from
mathematical or mechanized proofs. It is the stopping line before plugin-system
engineering: claims about capabilities, packages, transactions, reasoning
graphs, indices, and triggers remain specifications until those structures
exist in code.

## Evidence levels

| Mark | Meaning |
|---|---|
| **E-closed** | An executable property directly exercises the current implementation over a generated domain or explicit exhaustive boundary. It can still miss counterexamples outside that domain. |
| **E-partial** | Useful executable evidence exists, but the stated property has a wider domain or an uncovered boundary. |
| **F-open** | A mathematical or mechanized proof is possible against the current semantics but has not been completed. |
| **Engineering-blocked** | A meaningful implementation theorem needs a representation or enforcement seam that does not exist yet. |

## Proof sketches worth preserving

### Finite-budget evaluator termination

`Budget.steps` is a natural number. Each entry to `eval` and `apply`, and each
macro expansion, calls `tick`, which performs checked subtraction and returns a
budget error at zero. Therefore an execution containing infinitely many such
transitions cannot occur under a finite step budget. The remaining formal
obligation is to show that no evaluator path performs unbounded work between
charged transitions. Native builtins are part of that assumption boundary.

The recursion-depth check is an independent safety bound, not the termination
measure. It prevents an excessively deep closure call stack before the larger
step budget is consumed.

### Notebook graph preservation

Let `links(a, b)` mean live note `a` contains live target `b`, and let
`backs(b, a)` mean the derived backlink set for `b` contains `a`. The invariant
is:

```text
backs(b, a) iff links(a, b)
```

plus uniqueness, absence of self-links, and live targets. The empty notebook
satisfies the invariant. Create adds no edges. Link validates both endpoints and
updates both directions. Unlink removes both directions. Remove deletes the
outgoing reverse entries and removes every incoming link. The state-machine
property checks this immediately after every transition, including failed
operations and IDs that have already been removed.

### Formula non-mutation

`eval_formula` creates a fresh interpreter, registers only reader builtins, and
binds `self` to an immutable note snapshot. The property compares complete
serialized state before and after arbitrary generated source. This closes the
current entry point's observational non-mutation claim. It does not imply
non-escalation for a future plugin system because native registrations carry no
capability metadata yet.

## Engineering boundary

The next security statements are **engineering-blocked**:

- capability non-escalation and attenuation;
- package-resolution determinism and lockfile replay;
- package integrity, signatures, and provenance;
- atomic plugin mutation and rollback;
- deterministic reasoning/index/trigger implementation conformance;
- system-wide progressive-disclosure gating.

The first required seam is capability-bearing native registration plus an
explicit evaluation authority context. Until that exists, formula purity is a
property of the separate reader-only constructor, not a theorem covering all
extension execution.
